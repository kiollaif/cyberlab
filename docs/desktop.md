# Настольные сборки CYBERLAB

Исходники и история SQLite остаются общими для Windows и Linux. PyInstaller
добавляет интерпретатор Python, PySide6, плагины Qt, русский перевод и ресурсы.
На компьютере ученика не нужны Python, uv, VS Code и команды терминала.

## Скачать и установить

В [GitHub Actions → Desktop builds](https://github.com/kiollaif/cyberlab/actions/workflows/desktop.yml)
откройте успешный запуск нужной ветки. Внизу страницы находятся **Artifacts**.
Для скачивания артефактов GitHub требуется вход в аккаунт. Срок хранения —
90 дней для Windows/AppImage и 30 дней для экспериментального RPM.

| Артефакт | Что находится внутри |
| --- | --- |
| `CyberLab-Windows-x86_64` | `CyberLab-Setup.exe`, `CyberLab.exe`, SHA256 и отчёты запуска |
| `CyberLab-Linux-x86_64` | `CyberLab-x86_64.AppImage`, SHA256 и отчёт запуска |
| `CyberLab-ALT-p11-unverified-candidate` | RPM-кандидат и результаты проверки ALT Container p11; это не проверка Альт Образование |
| `CyberLab-desktop-kde-reports`, `CyberLab-desktop-gnome-reports` | Результат запуска с настоящим оконным менеджером, его имя и журнал |

**Windows:** распакуйте ZIP артефакта, дважды нажмите `CyberLab-Setup.exe` и
завершите установку. Программа устанавливается для текущего пользователя,
без запроса прав администратора. Появятся ярлыки на рабочем столе и в «Пуск».
Удаление доступно через «Установленные приложения» Windows. Отдельный
`CyberLab.exe` также запускается двойным нажатием без установки и консоли.
Первая распаковка EXE во временный каталог может занять несколько секунд.
Сборки пока не подписаны сертификатом: Windows может показать SmartScreen.

**Linux x86_64:** распакуйте ZIP, переместите AppImage в постоянную папку.
В свойствах файла разрешите выполнение как программы, затем запустите двойным
нажатием. После первого запуска CYBERLAB добавится в меню приложений с иконкой.
Не перемещайте AppImage после этого; если переместили — один раз запустите
его из новой папки, чтобы обновить путь в меню. Регистрация не требует root.
Для удаления достаточно удалить AppImage и пункт `cyberlab.desktop` из
пользовательской папки приложений; история сохраняется отдельно.

AppImage требует x86_64, glibc не ниже 2.35, графическую сессию X11 или
совместимую с Qt сессию Wayland, системные OpenGL/EGL и поддержку FUSE.
Архив GitHub не сохраняет разрешение на выполнение: его нужно включить
в файловом менеджере. Это действие не требует терминала.
Старые дистрибутивы, в том числе ветка ALT p10 с glibc ниже 2.35, не являются
целевой платформой этой сборки. Проверка Wayland отдельно ещё необходима.

**RPM:** кандидат называется `CyberLab-alt-p11-unverified.rpm` намеренно.
Его нельзя объявлять готовым пакетом для Альт Образование. После успешного
тестирования именно на установленной Альт Образование пакет можно открыть
через графический менеджер пакетов; ярлык и иконка устанавливаются в системное
меню. До такой проверки файл `CyberLab.rpm` как подтверждённый выпуск не публикуется.

## Пользовательские данные и работа без интернета

И установленная, и переносимая сборки используют прежние имена приложения
и организации Qt — `CYBERLAB`. Существующая история не переносится и не удаляется:

- Windows: `%LOCALAPPDATA%\CYBERLAB\CYBERLAB\cyberlab.sqlite3`.
- Linux: `$XDG_DATA_HOME/CYBERLAB/CYBERLAB/cyberlab.sqlite3`, по умолчанию
  `~/.local/share/CYBERLAB/CYBERLAB/cyberlab.sqlite3`.
- Настройки обучения: прежний `QSettings` в реестре Windows / XDG Config Home.
- AppImage: ярлык в `$XDG_DATA_HOME/applications/cyberlab.desktop`, иконка в
  `$XDG_DATA_HOME/icons/hicolor/256x256/apps/cyberlab.png`.

Установщик и RPM не включают базы данных, ключи API и настройки разработчика.
Удаление программы не удаляет историю. Симуляция, дерево решений, сравнение и
локальный наставник работают без сети. Необязательный DeepSeek включается
только кнопкой при наличии `DEEPSEEK_API_KEY`. Переменную можно задать через
графический редактор переменных среды Windows; затем заново открыть программу.
Для запуска с ярлыка она должна быть задана в окружении пользовательской сессии.

## Как устроена сборка

- `packaging/launcher.py` вызывает обычный `cyberlab.app.main()`.
- `packaging/CyberLab.spec` собирает один EXE на Windows и каталог на Linux.
  `console=False` задаёт графическую подсистему Windows. Ресурсы лежат рядом
  с модулем и одинаково доступны в wheel и сборке PyInstaller.
- `packaging/windows/CyberLab.iss` — русский установщик Inno Setup, ярлыки и
  удаление. Он меняет только каталог приложения и ярлыки.
- `scripts/build_desktop.py` запускает PyInstaller, создаёт AppDir и AppImage,
  записывает SHA256. AppImage-инструменты скачиваются с официальных GitHub
  releases и проверяются по зафиксированным контрольным суммам до выполнения.
  При изменении `continuous` runtime сумма перестанет совпадать: нужно проверить
  новый выпуск и осознанно обновить hash, а не отключать проверку.
- `packaging/linux/AppRun` запускает вложенный исполняемый файл.
- `packaging/linux/cyberlab.desktop` и `cyberlab.spec` — меню и RPM для ALT p11.
  Python/Qt включены в `/opt/cyberlab`, системные библиотеки указаны в Requires.
- `packaging/linux/build_rpm.sh` собирает RPM в официальном `alt:p11`, устанавливает,
  запускает с Xvfb, проверяет и удаляет. Имя отчёта прямо указывает на контейнер.
- `src/cyberlab/desktop.py` загружает иконку и регистрирует AppImage в меню.
  Путь в Exec экранируется по правилам desktop entry, без запуска shell.
- `src/cyberlab/diagnostics.py` — скрытая проверка готовой программы. Использует
  временную SQLite, настоящий Qt event loop и фонового локального наставника.
  Обычный запуск этот режим не включает.
- `scripts/verify_desktop.py` запускает готовый файл из пустой папки с пробелами,
  убирает Python/uv из PATH и проверяет JSON. Для EXE также читает PE-заголовок:
  подсистема должна быть GUI, а не консольной.
- `scripts/verify_installer.ps1` выполняет реальную тихую установку, проверяет
  оба ярлыка, запускает установленный EXE, удаляет программу и проверяет,
  что маркер в каталоге пользовательской истории остался.
- `scripts/check_desktop_session.sh` запускает KWin / GNOME Shell и проверяет
  `_NET_SUPPORTING_WM_CHECK` и имя оконного менеджера до проверки AppImage.
- `.github/workflows/desktop.yml` собирает на Windows и Ubuntu 22.04. Старшая
  glibc Ubuntu 22.04 — нижняя граница; сборка на новой Linux может её повысить.

## Повторить сборку разработчику

Это команды для разработчика, конечному пользователю они не нужны.

```sh
uv sync --locked --group build
uv run --locked --group build python scripts/build_desktop.py
```

Windows: после этого запустить Inno Setup 6 (`ISCC packaging/windows/CyberLab.iss`).
Linux: собирать на Ubuntu 22.04 x86_64 с зависимостями Qt из workflow или
`packaging/linux/Dockerfile.ubuntu`. PyInstaller не выполняет кросс-компиляцию.
Готовые файлы находятся в `dist/desktop/`; исходники и wheel собираются отдельно
прежней командой `uv build`. Группа `build` не нужна при обычной разработке.

## Что считается проверкой

Каждая платформа проходит исходные тесты, затем проверяется именно собранный
файл: окно, иконка, русский Qt, опасная ветка, возврат, безопасная ветка,
сравнение, локальный наставник, неизменность состояния и повторное открытие
SQLite. Python audit hook запрещает сеть в этом тесте; он не является
сетевой изоляцией нативного Qt на уровне ОС. Проверка запуска AppImage в CI
в режиме extract-and-run не подменяет проверку монтирования через FUSE.

Автотест с KWin/GNOME Shell на Xvfb проверяет взаимодействие с настоящим WM,
но не заменяет ручную проверку всей пользовательской сессии, файлового менеджера
и двойного нажатия. Windows runner не равен ручной проверке Windows 10/11.
Контейнер ALT p11 не равен установленной Альт Образование.

Фактические результаты сборки и ссылки на конкретный запуск CI записываются
ниже после выполнения. Наличие конфигурации не означает успешную сборку.

### Результаты этой доработки

- До изменений: 88 тестов прошли в облачной Linux-среде.
- После добавления ресурсов и интеграции: 93 теста прошли, Ruff прошёл.
- Запуск из исходников в офлайн-режиме: окно, русский перевод, обе ветки,
  сравнение, локальный наставник и повторное открытие SQLite прошли.
- Сборки Windows/AppImage, KDE/GNOME и RPM: результаты ещё ожидаются.
- Альт Образование, пользовательские Windows 10/11, Wayland: не проверены.
