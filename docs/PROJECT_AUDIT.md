### Проверка размера Windows

Старый тест требовал клиентское окно ровно 1366×768 на нативном рабочем столе.
Однако рамка окна и панель задач тоже занимают место, а Windows может ограничить
размер доступной рабочей областью. Новый вариант сохраняет весь пользовательский
маршрут и проверки текста, но рассчитывает целевой размер с учётом `frameGeometry`
и `availableGeometry` и требует его точного совпадения после обработки событий Qt.

Проверки **точных** 1280×720, 1366×768, 853×480 и 640×420 сохранены отдельно:
каждый случай запускает новый процесс Qt `offscreen`. Также остаются 125/150%.
Таким образом проверяется и нативное окно, и полный запрошенный размер;
исходная проблема не обходится отключением теста или допуском произвольного размера.

В удалённом Windows CI дополнительно обнаружена слишком большая минимальная ширина
списков сравнения при 640×420. `review_pages.py` теперь разрешает сжимать их по
горизонтали; полный текст сохраняется в подсказке и разборе пути. Проверка ждёт
до 5 секунд завершения расчёта Qt, но требования к ширине и высоте текста не ослаблены.

## Как проверяется офлайн-режим и пакет

`scripts/smoke_offline.py` устанавливает Python audit hook **до импорта приложения**.
Он запрещает DNS, connect, bind и sendto через Python socket и проверяет отсутствие
попыток даже при перехваченном исключении. Затем проходит GUI и проверяет историю.
Сценарий не запускает внешние команды и не открывает ссылки из учебного письма.
Клиент DeepSeek не создаёт сетевой запрос при запуске программы или переключении
экранов. Тест без API-ключа проверяет возврат к старым локальным правилам.

Это проверка операций Python, а не сетевых вызовов внутри нативных библиотек Qt.
Полная изоляция процесса через `unshare --user --map-root-user --net` в облаке
не удалась: `cannot open /proc/self/uid_map: Read-only file system`.
Проверка на физически отключённом от сети Windows/ALT здесь не заявляется.
Первичная установка зависимостей требует сети либо заранее заполненного кэша;
само установленное приложение работает с локальными данными.

`scripts/check_package.py` устанавливает wheel в новый временный venv без сети,
проверяет импорт из этого venv и выполняет smoke test из каталога вне checkout.
Проверяется именно поставляемый пакет, не editable-установка разработчика.
Зависимости экспортируются из `uv.lock` в временный `pylock.toml`, затем устанавливаются
с сохранёнными адресами wheel и хешами через `uv pip sync --offline`. Сам wheel
CYBERLAB устанавливается без повторного поиска зависимостей, после чего `uv pip check`
проверяет полноту окружения. Это работает и когда `uv sync --locked` наполнил кэш wheel,
но не кэш индекса PyPI. Конфигурация проекта и lock-файл при этом не изменяются.

## Повторение проверок

Из корня проекта:

```sh
uv sync --locked
uv run --locked pytest
uv run --locked ruff check .
uv run --locked ruff format --check .
uv build
uv run --locked python scripts/check_package.py
```

Без дисплея для последней команды задайте `QT_QPA_PLATFORM=offscreen`.
Для нативной Linux-проверки установите библиотеки из workflow, задайте
`QT_QPA_PLATFORM=xcb` и используйте `xvfb-run -a -s "-screen 0 1600x1000x24"`.
На Windows для нативных проверок используется `QT_QPA_PLATFORM=windows`.
