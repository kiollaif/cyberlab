| ID | Узлов | Маршрутов до итога | Что моделируется |

| fake-website-v1 | 7 | 8 | Проверка домена, известная закладка, учебная форма, отзыв посторонних сеансов |

Всего 31 маршрут. У каждого действия есть событие, изменение состояния и объяснение.
Риск — абсолютное учебное значение 0–100, а не вероятность реальной атаки.
Отключение USB не отменяет уже запущенную программу; отзыв сеансов не стирает
прежнюю утечку. При потере файлов из-за макросов пароль не объявляется раскрытым.
Это отдельные признаки, а не один общий флаг «плохой результат».

Настоящие вложения и устройства не читаются, программы и макросы не запускаются,
сайты не открываются в сети. События меняют только ComputerState. Виртуальные файлы
по-прежнему строки из VIRTUAL_FILES. Отдельно приложение сохраняет историю SQLite и настройки, а по явному выбору
пользователя — TXT. Установочная интеграция меню описана в desktop.md.

## Архитектура и сохранность истории

- `additional_scenarios.py` описывает три новых графа обычными именованными Choice/ScenarioNode.
- `scenarios.SCENARIOS` — простой реестр; выбор в окне вызывает `LabSession.switch_scenario`.
- `ComputerState` дополнен флагами attachment_opened, macros_enabled, usb_connected,
  malware_active, source_checked и threat_blocked. Их defaults — False.
- `source_checked` означает, что проверка выполнена, а не что источник надёжен.
- `mentor.explain_step` читает explanation только у уже выбранного действия.
- `reports.build_report` идёт по parent_id к предкам выбранного снимка, считает
  риск и берёт сохранённые события. Чужие ветки в TXT не попадают.
- `QSaveFile` записывает экспорт атомарно. Ошибка не меняет симуляцию и не выдаёт успех.
- QSettings хранит последнюю тему и отдельные feedback/<session_id>; прежний
  pending_feedback также читается. Настройки не подменяют записи SQLite.

Схема SQL остаётся **v1**, ALTER TABLE и перезапись старых строк не требуются.
Неизменённый тест открывает опубликованный дамп из `685ba05`: 14 снимков,
SQL-схема и исходные записи сравниваются до/после. Старый выбор открывает прежнюю
ветку без дубликата. Старый phishing-v1 не меняет последствия.
Совместимость здесь означает чтение старых данных новым кодом. Возвращаться к
старой сборке после записи новых сценариев не следует: она этих полей и тем не знает.

## Наставник

По умолчанию сохранены официальный DeepSeek, deepseek-flash, non-thinking,
350 токенов, timeout операций SDK 12 секунд и ноль автоповторов. Запрос только по кнопке.
ProviderConfig допускает local или custom OpenAI-совместимый API; параметры — в README.
Local отключает API независимо от ключа. Custom не получает специфичный thinking DeepSeek.

Контекст включает текущую ситуацию, уже сделанные действия и учебные признаки,
но не граф будущих событий, содержимое файлов и произвольные соседние ветки.
Модель не получает ссылку на LabSession/SQLite и не рассчитывает официальный риск.
Фоновые QThread, защита от повторного нажатия и отбрасывание устаревшего ответа сохранены.
При неверной конфигурации, отсутствии ключа, сетевой ошибке или ошибке API работают
локальные объяснения. Секреты в URL не разрешены; ключ хранится только в окружении.

Фильтр скрывает распространённые email, телефоны, sk-ключи и подписанные секреты.
Он не может гарантировать распознавание всех личных сведений: настоящие пароли и
персональные данные вводить нельзя. Живой платный API не вызывался; тесты используют
MockTransport настоящего OpenAI SDK и очищают личные API-переменные окружения.
